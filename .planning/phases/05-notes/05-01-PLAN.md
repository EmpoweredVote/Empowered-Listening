<task type="auto">
  <name>Task 1: Write and apply Phase 5 notes schema migration</name>
  <files>supabase/migrations/20260427000000_notes_phase5.sql</files>
  <action>
Create a new migration file at `supabase/migrations/20260427000000_notes_phase5.sql`.
Use UTC date 20260427 (today) as the prefix. The migration must:

1. ADD columns (idempotent via IF NOT EXISTS):
   - `updated_at timestamptz` (nullable; populated on edit only — NULL means never edited)
   - `is_edited boolean NOT NULL DEFAULT false`
   - `rebuttal_order integer` (nullable; NULL = not in rebuttal list)
   - `source_transcript_entry_id uuid REFERENCES listening.transcript_entries(id) ON DELETE SET NULL` (nullable)

2. DROP the `is_private` column (`ALTER TABLE listening.notes DROP COLUMN IF EXISTS is_private`).
   Rationale (CONTEXT.md): notes are always private. Keeping the column would let a future
   bug accidentally flip a note public.

3. DROP the existing select policy: `DROP POLICY IF EXISTS "notes_select_own_or_public" ON listening.notes`.

4. CREATE new owner-only select policy:
   ```
   CREATE POLICY "notes_select_own"
     ON listening.notes
     FOR SELECT
     TO authenticated
     USING ((select auth.uid()) = user_id);
   ```

5. Add a partial index to make the rebuttal checklist query cheap:
   `CREATE INDEX IF NOT EXISTS notes_rebuttal_order_idx
      ON listening.notes (debate_id, user_id, rebuttal_order)
      WHERE rebuttal_order IS NOT NULL;`

6. Add a comment header at the top of the file matching the existing migration
   style (`-- Phase 5: notes — align schema with always-private design`).

DO NOT modify the existing `notes_insert_own`, `notes_update_own`, or
`notes_delete_own` policies — they already gate on `user_id` and remain valid.

After writing the migration, apply it to the linked Supabase project with:
`npx supabase db push` (the project is already linked to kxsdzaojfaibhuzmclfq —
see Phase 1 SUMMARY).  If `db push` is non-interactive in this environment,
fall back to applying via the Supabase SQL editor instructions noted in
prior phase summaries; either way, verify the migration applied before
declaring done.
  </action>
  <verify>
