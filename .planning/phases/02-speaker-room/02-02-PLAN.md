**Create `lib/db/pool.ts`** — Singleton node-postgres Pool for writes to the `listening` schema.  PostgREST does not expose non-public schemas, so all Phase 2 server-side writes go through this.

```typescript
import { Pool } from 'pg';
import { env } from '@/lib/env';

// Module-level singleton — Node.js runtime (Render) reuses the same process across requests.
let _pool: Pool | null = null;

export function getPool(): Pool {
  if (!_pool) {
    if (!env.DATABASE_TRANSACTION_POOLER_URL) {
      throw new Error('DATABASE_TRANSACTION_POOLER_URL is not set');
    }
    _pool = new Pool({
      connectionString: env.DATABASE_TRANSACTION_POOLER_URL,
      // Supabase transaction pooler expects SSL
      ssl: { rejectUnauthorized: false },
    });
  }
  return _pool;
}

export const pool = {
  query: (text: string, params?: unknown[]) => getPool().query(text, params),
};
```

Using the `pool` object wrapper lets callers use `pool.query(sql, params)` without repeatedly calling `getPool()`.  Lazy initialization avoids errors in dev environments where DATABASE_TRANSACTION_POOLER_URL is not set (e.g., pure UI work).

**Create `lib/livekit/tokens.ts`** — mintToken factory with role-specific grants.

```typescript
import { AccessToken, type VideoGrant } from 'livekit-server-sdk';
import { env } from '@/lib/env';

export type ParticipantRole = 'speaker' | 'moderator';

export interface MintTokenInput {
  identity: string;     // canonical format: `${debateId}:${userId}`
  roomName: string;     // canonical format: `ld-${debateId}`
  role: ParticipantRole;
  ttlSeconds?: number;  // default 4 hours — covers longest LD debate with buffer
}

export async function mintToken(input: MintTokenInput): Promise<string> {
  if (!env.LIVEKIT_API_KEY || !env.LIVEKIT_API_SECRET) {
    throw new Error('LiveKit credentials are not configured');
  }

  const at = new AccessToken(env.LIVEKIT_API_KEY, env.LIVEKIT_API_SECRET, {
    identity: input.identity,
    ttl: input.ttlSeconds ?? 60 * 60 * 4,
  });

  const grant: VideoGrant = {
    room: input.roomName,
    roomJoin: true,
    canSubscribe: true,
    // Speakers can publish their mic; moderator does not publish (AV spectator role).
    canPublish: input.role === 'speaker',
    // Both roles can send data messages (used for UI-side signals like prep-request).
    canPublishData: true,
    // Moderator needs roomAdmin to call RoomServiceClient.updateParticipant from the server
    // on behalf of the moderator's session.  Speakers must NOT have roomAdmin.
    roomAdmin: input.role === 'moderator',
  };

  at.addGrant(grant);

  // toJwt() is async in livekit-server-sdk v2 — awaiting is REQUIRED.
  // Omitting await returns a pending Promise, which LiveKit will reject as a malformed token.
  return at.toJwt();
}
```

**Create `lib/livekit/room-service.ts`** — Shared RoomServiceClient + setMicPermission helper.

```typescript
import { RoomServiceClient } from 'livekit-server-sdk';
import { env } from '@/lib/env';

// Single shared instance — RoomServiceClient is safe to reuse across requests.
// Lazy init so modules that import this during server startup do not crash if env is missing.
let _roomService: RoomServiceClient | null = null;

export function getRoomService(): RoomServiceClient {
  if (!_roomService) {
    if (!env.LIVEKIT_URL || !env.LIVEKIT_API_KEY || !env.LIVEKIT_API_SECRET) {
      throw new Error('LiveKit credentials are not configured');
    }
    _roomService = new RoomServiceClient(env.LIVEKIT_URL, env.LIVEKIT_API_KEY, env.LIVEKIT_API_SECRET);
  }
  return _roomService;
}

// Grant or revoke a participant's ability to publish (mic control).
// This is the canonical pattern for LD segment transitions — preferred over mutePublishedTrack
// because revoking canPublish auto-unpublishes all tracks and prevents re-publishing.
export async function setMicPermission(
  roomName: string,
  identity: string,
  canPublish: boolean,
): Promise<void> {
  await getRoomService().updateParticipant(roomName, identity, {
    permission: {
      canPublish,
      canSubscribe: true,
      canPublishData: true,
    },
  });
}
```

Critical notes:
- `mintToken` must await `at.toJwt()` — skipping `await` is the #1 LiveKit v2 foot-gun (Pitfall 2 in RESEARCH.md).
- Moderator tokens have `canPublish: false` (no mic publish) and `roomAdmin: true` (so server-side `updateParticipant` calls made on behalf of the moderator's session succeed).  Speakers have the inverse: `canPublish: true`, `roomAdmin: false`.
- CX segment mic handling is done at the segment transition layer (02-06), not in the token — tokens are issued once at join and never reissued per-segment.  Mid-debate permission changes go through `setMicPermission` on the server.
- Do NOT use `mutePublishedTrack` — it is track-specific, requires a prior `getParticipant` call to find the SID, and re-unmuting requires `enable_remote_unmute` in LiveKit Cloud settings.  `updateParticipant` with `canPublish` is the right tool.
