A. Create `hooks/useUserRole.ts`:

```typescript
'use client';
import { useEffect, useState } from 'react';
import { useSession } from '@/components/auth/SessionProvider';
import { useDebateStore } from '@/store/debateStore';
import { decodeJwt } from 'jose';   // already a dep via lib/auth/jwks.ts

export type UserRole = 'observer' | 'speaker' | 'moderator' | 'anonymous';

export interface UserRoleState {
  userId: string | null;
  displayName: string | null;
  userRole: UserRole;
  tier: 'inform' | 'connected' | 'empowered' | null;
  token: string | null;
  loading: boolean;
}

export function useUserRole(): UserRoleState { /* ... */ }
```

Implementation:
1. Pull `{ token, displayName, loading }` from `useSession()`.
2. Decode `token` with `jose.decodeJwt` to extract `sub` (userId). Wrap in
   try/catch — invalid tokens → userId=null. (Verification of signature
   already happens server-side; we only need claims here.)
3. Pull `speakers` from `useDebateStore`. The user is a "speaker" iff their
   userId matches any `debate_speaker.user_id` with role in {affirmative,
   negative}. They are a "moderator" iff role==='moderator'. Otherwise they
   are an "observer" if they have a token, "anonymous" if they don't.
4. Tier requires a fetch to /api/account/me — to keep this hook lightweight,
   fetch tier ONLY when token is present. Cache in component state. Set tier
   to null while loading. (Note: we accept a brief delay between mount and
   tier-known; consumers must show a loading state when `loading: true`.)
5. Return all five fields.

Note: NotesPanel only needs userRole !== 'anonymous' && tier !== 'inform' to
show the input. The hook returning null tier briefly is fine — we render the
notes list optimistically and gate the input behind tier check.

B. Create `components/notes/NoteInput.tsx`:

```typescript
'use client';
import { useState, useRef, useEffect } from 'react';
import { useDebateStore } from '@/store/debateStore';
import { useNotesStore, type NoteRow } from '@/store/notesStore';
import { computeDebateTimeMmss } from '@/lib/transcription/debate-time';

interface NoteInputProps {
  debateId: string;
  token: string;                 // Bearer token; parent has already gated for connected tier
  onSaved?: () => void;          // optional — parent collapses input after save
  initialFocus?: boolean;        // when true (e.g. opened via N keypress), autofocus
}
```

Behavior:
1. Single `<textarea>` with rows=2 (auto-grows up to 6) bound to local state.
2. Sticky positioning: parent (NotesPanel) wraps it in a `sticky bottom-0`
   container. Inside, render: textarea + a small "Save" button (mouse path)
   + helper text "Enter to save · Shift+Enter for newline".
3. Keyboard handler on textarea:
   - Enter (no shift, no IME): preventDefault, call save().
   - Shift+Enter: native textarea behavior (newline).
4. `save()`:
   a. Trim content; if empty, do nothing.
   b. Compute `debate_time_mmss`:
      - Get active segment from useDebateStore.getState().getActiveSegment().
      - If none active or no actual_start, set debate_time_mmss = null.
      - Otherwise: `computeDebateTimeMmss(new Date(active.actual_start), new Date())`.
   c. POST to `/api/debates/${debateId}/notes` with Authorization Bearer
      header, JSON body `{ content, debateTimeMmss, sourceTranscriptEntryId: null }`.
   d. On success: parse response, call `useNotesStore.getState().addNote(note)`,
      clear textarea, call `onSaved?.()`.
   e. On 4xx: show inline error message above textarea (toast-style state for
      ~3 seconds, then auto-clear).
   f. On 5xx/network error: same inline error; do NOT clear textarea.
5. Disable textarea while a save is in flight (single-flight via useRef bool).

Render structure (top to bottom in a flex-col h-full):
1. Header bar (shrink-0, border-b, px-3 py-2):
   - Left: title "Notes".
   - Right: two buttons:
     - "+ Add note" — sets `inputOpen` state and focuses the input.
     - "Export PDF" — opens `/api/debates/${debateId}/notes/export` in a new
       tab. Implementation: build a fetch call with the bearer token, then
       blob → object URL → anchor click. Cannot use a plain `<a href>`
       because the route requires Authorization. Code:
       ```
       const res = await fetch(`/api/debates/${debateId}/notes/export`, {
         headers: { Authorization: `Bearer ${token}` },
       });
       if (!res.ok) { /* show toast 'Export failed' */ return; }
       const blob = await res.blob();
       const url = URL.createObjectURL(blob);
       const a = document.createElement('a');
       a.href = url;
       a.download = `debate-notes-${debateId}.pdf`;
       a.click();
       URL.revokeObjectURL(url);
       ```
2. Scrollable list (flex-1 min-h-0 overflow-y-auto px-3 py-2 space-y-2):
   - Empty state: "No notes yet. Press N or click + Add note to start."
     (only shown when notes.length === 0 AND user is connected+).
   - Otherwise: render notes sorted by `created_at` ASC (so newest at the
     bottom — matches transcript flow).  Map each to <NoteItem>.
3. Sticky input region (shrink-0, border-t, px-3 py-2):
   - If userRole === 'anonymous' → "Sign in to take notes" link to accounts.empowered.vote.
   - If tier === 'inform' → "Upgrade to Connected to take notes" message
     (no link — copy decision; account upgrade flow is out of scope).
   - Otherwise (connected/empowered, including speakers and moderators):
     mount <NoteInput debateId={...} token={...} initialFocus={inputOpen}
     onSaved={() => setInputOpen(false)}/>.
