A. Create `lib/notes/align-notes-to-transcript.ts` exporting one function:

```typescript
export interface AlignedNote {
  id: string;
  content: string;
  debate_time_mmss: string | null;
  is_edited: boolean;
  /** Index in the transcript array of the nearest-earlier entry; -1 means
   *  this note has no earlier transcript entry and should render at the top. */
  alignedTranscriptIndex: number;
}

export interface TranscriptForAlignment {
  id: string;
  debate_time_mmss: string;
}

export interface NoteForAlignment {
  id: string;
  content: string;
  debate_time_mmss: string | null;
  is_edited: boolean;
}

export function alignNotesToTranscript(
  notes: NoteForAlignment[],
  transcript: TranscriptForAlignment[],
): AlignedNote[];
```

Algorithm (per RESEARCH.md Pitfall #6 — "nearest earlier transcript entry"):
1. Convert "M:SS" or "MM:SS" or "MMM:SS" to total seconds (helper
   `mmssToSeconds(s: string): number`). Strings already validated upstream;
   return 0 if format is unexpected.
2. Sort transcript ASC by debate_time_mmss seconds.
3. For each note (preserve input order in output):
   - If `note.debate_time_mmss === null`, alignedTranscriptIndex = -1.
   - Otherwise binary search (or simple linear scan — transcripts are bounded
     small) for the highest transcript index where transcript[i].seconds <=
     note.seconds. If none found, -1.
4. Return new AlignedNote[] preserving the original input order of notes.

Do NOT mutate the inputs. Do NOT use Date — debate_time_mmss is a string
elapsed-time format, not a wall clock.

B. Create `lib/notes/align-notes-to-transcript.test.ts` with at least these
   cases (use Vitest, mirroring `lib/transcription/debate-time.test.ts` style):
   1. Empty inputs → `alignNotesToTranscript([], [])` returns `[]`.
   2. Empty transcript with notes → every note has alignedTranscriptIndex = -1.
   3. Note exactly at a transcript entry's time → aligns to that entry's index.
   4. Note between two transcript entries (e.g., note at 3:15 with transcript
      entries at 2:50, 3:10, 3:30) → aligns to the 3:10 entry (index where
      that entry sits in the sorted array).
   5. Note before the first transcript entry → alignedTranscriptIndex = -1.
   6. Notes with null debate_time_mmss → alignedTranscriptIndex = -1.
   7. Output preserves input note order.
  </action>

Create `app/api/debates/[debateId]/notes/export/route.ts`:

```typescript
export const runtime = 'nodejs';   // REQUIRED — renderToBuffer needs Node APIs (RESEARCH.md Pitfall #4)

import { NextRequest } from 'next/server';
import { renderToBuffer } from '@react-pdf/renderer';
import { getPool } from '@/lib/db/pool';
import { verifyToken } from '@/lib/auth/jwks';
import { getAccountMe } from '@/lib/auth/account';
import { DebateNotesPdf } from '@/components/pdf/DebateNotesPdf';
```

GET handler logic:
1. Resolve `params.debateId`.
2. Extract Bearer token; if missing → 401 plain text "Missing token".
3. Verify token; on failure → 401 "Invalid token". Get userId = payload.sub.
   (No tier check on EXPORT — even Inform-tier users can export their own
   notes since they can't have any. The export simply returns a debate-only
   PDF if there are zero notes. This avoids confusing an upgraded
   account who downgraded back.)
4. Fetch the four datasets in parallel via Promise.all using `pool.query`:
   a. Debate metadata: `SELECT id, topic, scheduled_at FROM listening.debates
      WHERE id = $1`. If no rows → 404.
   b. Speakers: `SELECT role, display_name FROM listening.debate_speakers
      WHERE debate_id = $1`.
   c. Transcript: `SELECT te.id, te.speaker_id, te.debate_time_mmss, te.text
      FROM listening.transcript_entries te WHERE te.debate_id = $1
      ORDER BY te.spoken_at ASC` (no limit — full transcript needed for export).
   d. Notes: `SELECT id, content, debate_time_mmss, is_edited
      FROM listening.notes WHERE debate_id = $1 AND user_id = $2
      ORDER BY created_at ASC`.
5. Fetch exporter display_name from `getAccountMe(bearer)`. If account fetch
   fails, fall back to `'You'` so the export does not 500 on transient
   account-service errors.
6. Build the `transcript` prop array by joining transcript rows with the
   speakers map: each entry → `{ id, debate_time_mmss, text, speakerName,
   speakerLabel: 'Aff'|'Neg'|'Mod' }`. Map role → label same as
   TranscriptEntry.tsx (affirmative→Aff, negative→Neg, moderator→Mod).
7. Build the `debate` prop: title from topic, date formatted as
   `new Date(scheduled_at).toISOString().slice(0,10)` (YYYY-MM-DD); names from
   the speakers map (find by role; if missing, use placeholder strings
   "Affirmative Speaker", etc — never throw).
8. `const buffer = await renderToBuffer(<DebateNotesPdf debate={...}
   exporterName={...} notes={notes} transcript={transcript} />);`
9. Return:
   ```
   return new Response(new Uint8Array(buffer), {
     status: 200,
     headers: {
       'Content-Type': 'application/pdf',
       'Content-Disposition': `attachment; filename="debate-notes-${debateId}.pdf"`,
       'Cache-Control': 'no-store',
     },
   });
   ```
   (Use Uint8Array view to satisfy the Response body type; Buffer is also
   valid in Node runtime but Uint8Array is more portable.)

Wrap the entire handler in try/catch — on any throw log to console.error
with a `[notes-export]` prefix and return 500 plain text "Export failed".
  </action>
