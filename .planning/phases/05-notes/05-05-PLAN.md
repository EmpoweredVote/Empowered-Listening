<objective>
Build the speaker-specific rebuttal experience: a floating button that lets
speakers convert transcript selections into rebuttal notes, and a sortable
checklist that combines typed notes with flagged transcript lines into one
prioritized list with addressed-state checkboxes.

checkboxes) and the transcript-flagging half of CONTEXT.md's dual-source
rebuttal design. After this plan, a speaker on the observer page sees their
debate-prep tool wired up: select an opposing argument in the transcript →
add it to the list → reorder by importance → check off as addressed.

Output: Two new components, small edits to existing components from Plans
04 and the transcript surface, and surgical body-schema extensions to the
notes POST and single-note PUT routes from Plan 02. Speakers gain a
checklist UI; observers and moderators see no change in their flow.

Note on shared files: This plan modifies several files first introduced or
created by Plans 02 and 04 (the notes POST/PUT routes; TranscriptPanel;
NotesPanel; DesktopLayout/MobileLayout). Wave 4 is the only plan modifying
these files in the post-Wave-3 timeline, so there is no merge conflict risk.
The amendments are strictly additive: optional fields and conditional
rendering paths.

A. Extend the POST body schema in `app/api/debates/[debateId]/notes/route.ts`:

Add `addToRebuttal: z.boolean().optional()` to the existing zod schema. When
`addToRebuttal === true`, the INSERT should set `rebuttal_order` to
`COALESCE(MAX(rebuttal_order)+1, 0)` for the (user_id, debate_id) pair. Use
a CTE to compute the max in the same statement:

```sql
WITH next_order AS (
  SELECT COALESCE(MAX(rebuttal_order)+1, 0) AS ord
  FROM listening.notes
  WHERE user_id = $1 AND debate_id = $2
)
INSERT INTO listening.notes
  (user_id, debate_id, content, debate_time_mmss, source_transcript_entry_id,
   rebuttal_order, created_at)
VALUES
  ($1, $2, $3, $4, $5,
   CASE WHEN $6::boolean THEN (SELECT ord FROM next_order) ELSE NULL END,
   NOW())
RETURNING id, debate_id, content, debate_time_mmss, created_at, updated_at,
          is_edited, rebuttal_order, source_transcript_entry_id;
```

When `addToRebuttal` is omitted or false, `rebuttal_order` stays NULL — same
as the existing Plan 02 behavior. Backward-compatible.

B. Extend the PUT body schema in `app/api/debates/[debateId]/notes/[noteId]/route.ts`:

Replace the schema:
```
z.object({
  content: z.string().trim().min(1).max(2000).optional(),
  rebuttalOrder: z.union([z.number().int().nonnegative(), z.null()]).optional(),
}).refine(b => b.content !== undefined || b.rebuttalOrder !== undefined,
           { message: 'Provide content or rebuttalOrder' });
```

The UPDATE statement uses COALESCE so each column is updated only when its
field was sent:
```sql
UPDATE listening.notes
SET
  content = COALESCE($1, content),
  is_edited = CASE WHEN $1 IS NOT NULL THEN true ELSE is_edited END,
  updated_at = CASE WHEN $1 IS NOT NULL THEN NOW() ELSE updated_at END,
  rebuttal_order = CASE WHEN $5::boolean THEN $2 ELSE rebuttal_order END
WHERE id = $3 AND debate_id = $4 AND user_id = $userIdParam
RETURNING ...;
```

Pass an explicit boolean parameter "rebuttalOrder was sent" so the CASE knows
when to apply the new value (which might itself be null/0). The handler must
build that boolean from `parsed.data.rebuttalOrder !== undefined`.

Behavior:
1. Read `notes` and `checkedIds` from useNotesStore.
2. Build `rebuttalNotes` via useMemo: notes with `rebuttal_order !== null`,
   sorted by rebuttal_order ASC.
3. Track `activeId: string | null` for DragOverlay rendering.
4. Set up sensors: PointerSensor + KeyboardSensor with sortableKeyboardCoordinates.
5. Render structure:
   - DndContext with sensors, collisionDetection={closestCenter},
     onDragStart={(e) => setActiveId(e.active.id as string)},
     onDragEnd handler:
     ```
     setActiveId(null);
     const { active, over } = event;
     if (!over || active.id === over.id) return;
     const oldIndex = rebuttalNotes.findIndex(n => n.id === active.id);
     const newIndex = rebuttalNotes.findIndex(n => n.id === over.id);
     const newRebuttal = arrayMove(rebuttalNotes, oldIndex, newIndex);

     // Optimistically update store: assign new rebuttal_order to each
     const updated = newRebuttal.map((n, i) => ({...n, rebuttal_order: i}));
     useNotesStore.getState().setNotes([
       ...notes.filter(n => n.rebuttal_order === null),
       ...updated,
     ]);

     // Persist
     void fetch(`/api/debates/${debateId}/notes/${newRebuttal[0].id}/reorder`, {
       method: 'PUT',
       headers: { 'Content-Type': 'application/json', Authorization: `Bearer ${token}` },
       body: JSON.stringify({ orderedIds: newRebuttal.map(n => n.id) }),
     }).catch(err => console.error('[reorder]', err));
     ```
   - SortableContext with items=rebuttalNotes.map(n => n.id),
     strategy=verticalListSortingStrategy.
   - For each note render `<SortableRebuttalItem key={n.id} note={n}
       checked={!!checkedIds[n.id]} onToggle={() => setChecked(n.id, !checkedIds[n.id])}
       onDemote={() => demoteNote(n.id)} />`.
   - DragOverlay rendering a static (non-sortable) version of the dragged
     item when activeId is set.

6. Sub-component SortableRebuttalItem:
```typescript
function SortableRebuttalItem({ note, checked, onToggle, onDemote }: {
  note: NoteRow; checked: boolean; onToggle(): void; onDemote(): void;
}) {
  const { attributes, listeners, setNodeRef, transform, transition, isDragging } = useSortable({ id: note.id });
  const style = { transform: CSS.Transform.toString(transform), transition, opacity: isDragging ? 0.4 : 1 };
  return (
    <div ref={setNodeRef} style={style} className="flex items-start gap-2 p-2 bg-slate-900 border border-slate-800 rounded-md">
      <span {...attributes} {...listeners} className="cursor-grab text-slate-500 select-none" aria-label="Drag to reorder">⋮⋮</span>
      <input type="checkbox" checked={checked} onChange={onToggle} className="mt-1" />
      <div className={`flex-1 text-sm ${checked ? 'line-through opacity-60' : ''}`}>
        {note.debate_time_mmss && <span className="text-xs text-slate-500 mr-1">@{note.debate_time_mmss}</span>}
        <span>{note.content}</span>
        {note.is_edited && <span className="text-xs italic text-slate-500 ml-1">(edited)</span>}
      </div>
      <button onClick={onDemote} aria-label="Remove from rebuttal list" className="text-slate-500 hover:text-slate-300">×</button>
    </div>
  );
}
```
