  <name>Task 1: Connected-tier helper + GET/POST notes route</name>
  <files>lib/auth/connected.ts, app/api/debates/[debateId]/notes/route.ts</files>
  <action>
A. Create `lib/auth/connected.ts` exporting `requireConnectedTier(accessToken: string)`:
   - Calls `getAccountMe(accessToken)` from `@/lib/auth/account.ts`.
   - Throws an Error with `.code = 'INFORM_TIER'` if `account.tier === 'inform'`.
   - Throws Error with `.code = 'STANDING'` if `account.account_standing !== 'active'`.
   - Returns the account object on success.
   - Export a small `mapTierError(err): { status: number; body: { error: string } }`
     helper so route handlers can convert thrown errors into uniform responses
     (403 INFORM_TIER → "Connected account required"; 403 STANDING →
     "Account standing prevents this action"; otherwise 500 "Internal error").

B. Create `app/api/debates/[debateId]/notes/route.ts`:
   - `export const runtime = 'nodejs';` at top.
   - Import: NextRequest, NextResponse, getPool, verifyToken, requireConnectedTier, mapTierError, z (zod).
   - Define and EXPORT a `NoteRow` type matching the columns the API returns:
     `{ id: string; debate_id: string; content: string; debate_time_mmss: string | null; created_at: string; updated_at: string | null; is_edited: boolean; rebuttal_order: number | null; source_transcript_entry_id: string | null; }`.
   - Helper `getUserIdFromRequest(req)` mirroring the pattern in
     RESEARCH.md (Bearer token → verifyToken → payload.sub) — return null on
     any failure.

   GET handler:
   1. Resolve params, get userId. If null → 401 `{ error: 'Missing token' }`.
   2. Confirm debate exists (single SELECT 1 from listening.debates) → 404 if not.
   3. SELECT all notes columns (in the NoteRow shape) from listening.notes
      WHERE debate_id = $1 AND user_id = $2 ORDER BY created_at ASC.
   4. Respond `{ notes: rows }` with `Cache-Control: no-store`.

   POST handler:
   1. Resolve params, get userId; 401 if missing.
   2. Call `requireConnectedTier(bearer)`. On thrown error → mapTierError
      response.
   3. Validate body via zod:
      ```
      z.object({
        content: z.string().trim().min(1).max(2000),
        debateTimeMmss: z.string().regex(/^\d{1,3}:\d{2}$/).nullable(),
        sourceTranscriptEntryId: z.string().uuid().nullable().optional(),
      })
      ```
      Reject 400 on parse failure.
   4. INSERT INTO listening.notes (user_id, debate_id, content, debate_time_mmss,
      source_transcript_entry_id, created_at) VALUES ($1,$2,$3,$4,$5, NOW())
      RETURNING (all NoteRow columns).
   5. Respond 201 `{ note: rows[0] }`.

Do NOT call any non-public Supabase client — every query goes through `getPool()`.
  </action>

A. Create `app/api/debates/[debateId]/notes/[noteId]/route.ts`:
   - `export const runtime = 'nodejs';`
   - Reuse the same `getUserIdFromRequest`, `requireConnectedTier`, `mapTierError`
     pattern (import from Task 1's helpers).

   PUT handler:
   1. Resolve params { debateId, noteId }. Get userId; 401 if missing.
   2. requireConnectedTier; map error to 403 if thrown.
   3. zod-validate body: `z.object({ content: z.string().trim().min(1).max(2000) })`.
   4. UPDATE listening.notes SET content = $1, is_edited = true, updated_at = NOW()
      WHERE id = $2 AND debate_id = $3 AND user_id = $4 RETURNING (NoteRow shape).
   5. If rowCount === 0 → 404 `{ error: 'Note not found' }`. (Same response for
      "doesn't exist" and "not yours" — DO NOT leak ownership info.)
   6. Respond `{ note: rows[0] }`.

   DELETE handler:
   1. Resolve params, get userId; 401 if missing.
   2. (No tier check on delete — user can always remove their own data.)
   3. DELETE FROM listening.notes WHERE id = $1 AND debate_id = $2 AND user_id = $3.
   4. If rowCount === 0 → 404; else respond 204 (`new Response(null, { status: 204 })`).

B. Create `app/api/debates/[debateId]/notes/[noteId]/reorder/route.ts`:
   Note: The route is path-scoped to a single noteId for URL symmetry, but the
   body carries the FULL ordered list of note IDs that the client wants
   persisted in this rebuttal list (this is the established pattern for
   reorder operations — one HTTP call per drag-end, not N calls).

   PUT handler:
   1. Resolve params { debateId, noteId }. Note: noteId here is informational
      (latest moved item) — server does not require it to match.
   2. Get userId; 401 if missing. requireConnectedTier; 403 if thrown.
   3. zod body: `z.object({ orderedIds: z.array(z.string().uuid()).min(1).max(500) })`.
   4. Fetch ownership: `SELECT id FROM listening.notes WHERE debate_id = $1 AND
      user_id = $2 AND id = ANY($3::uuid[])`. If `rows.length !== orderedIds.length`,
      respond 400 `{ error: 'Some notes do not belong to this user/debate' }`.
   5. In a single transaction (use `pool.connect()` to get a client):
      - BEGIN
      - For each id in orderedIds with index i:
        `UPDATE listening.notes SET rebuttal_order = $1 WHERE id = $2`.
        Use a parameterized UPDATE with VALUES list and FROM clause to do
        all updates in one query — example:
        ```
        UPDATE listening.notes AS n
        SET rebuttal_order = v.ord::int
        FROM (VALUES (uuid1, 0), (uuid2, 1), ...) AS v(id, ord)
        WHERE n.id = v.id::uuid AND n.user_id = $userIdParam;
        ```
        Build the VALUES tuple and parameter array dynamically; the user_id
        check is the second-line defense.
      - COMMIT.
      - On any error, ROLLBACK and respond 500.
   6. Respond `{ ok: true }`.

Both files MUST set `export const runtime = 'nodejs';` at the top (route
handlers default to Edge runtime; pg requires Node).

Type contract (export both):

```typescript
export interface NoteRow {
  id: string;
  debate_id: string;
  content: string;
  debate_time_mmss: string | null;
  created_at: string;
  updated_at: string | null;
  is_edited: boolean;
  rebuttal_order: number | null;
  source_transcript_entry_id: string | null;
}

export interface NotesStoreState {
  notes: NoteRow[];                       // all of the user's notes for the active debate
  checkedIds: Record<string, boolean>;    // ephemeral, never persisted — speaker rebuttal "addressed" state
  setNotes(notes: NoteRow[]): void;
  addNote(note: NoteRow): void;
  updateNote(id: string, updates: Partial<NoteRow>): void;
  removeNote(id: string): void;
  reorderNotes(orderedIds: string[]): void;  // reorders in-memory list to match given order
  setChecked(id: string, checked: boolean): void;
  resetChecked(): void;
  reset(): void;
}
```

Implementation notes:
- `setNotes` replaces the whole list (used after fetching from GET).
- `addNote` appends.
- `updateNote` maps over notes, replacing matching id with `{...n, ...updates}`.
- `removeNote` filters by id; ALSO removes the id from `checkedIds`.
- `reorderNotes(orderedIds)` reconstructs the array in the given order, but ONLY
  for ids present in both the current notes and the orderedIds list. Keep notes
  not in orderedIds appended at the end (sorted by created_at). This is
  important because not all notes are in the rebuttal list — most observers
  use only the timeline view.
- `setChecked(id, checked)` sets `checkedIds[id] = checked`. `resetChecked` clears.
- `reset()` clears everything (notes=[], checkedIds={}).

DO NOT add an `is_checked` field to NoteRow — the checked state is purely
client-side and tracked in `checkedIds`. RESEARCH.md Pitfall #5 and Open
Question #2 both confirm this.
  </action>
